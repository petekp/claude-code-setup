# Human interfaces for agentic coding work

Research memo, 2026-10-04. Purpose: inform a side pane for Claude Code that keeps the human oriented and makes their input cheap and well-timed.

## Bottom line

- The strongest patterns: a shared plan both parties read, evidence instead of claims, a separate judge for "done", questions the agent asks in structured form, an inbox of typed requests, and boundaries plus undo instead of per-action approval.
- Most failures share one cause. They spend human attention at the wrong grain or moment, or hand the human a claim that is costly to check. Claude Code users approve 93% of permission prompts. In a lab study, people trusted plausible but wrong plans.
- Situation awareness has three levels: what is happening, whether it is on course, and what comes next. The products reviewed cover the first well and the second partly. Almost none say when the agent will next need the human, or for what. That gap is the best opening for a side pane.

## 1. Patterns that work

**1.1 A shared, living plan.** A written plan grounds both parties, and the agent needs it as much as the human. Claude Code's original todo tool did nothing in code; LangChain calls it a "no-op" whose value is keeping the agent on track ([LangChain](https://www.langchain.com/blog/deep-agents)). Manus keeps rewriting a todo.md so the goal stays in the model's recent attention ([Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)). Plan or spec modes in [Claude Code](https://code.claude.com/docs/en/best-practices), [Cursor](https://cursor.com/blog/plan-mode), [Kiro](https://kiro.dev/blog/introducing-kiro/), [Devin](https://cognition.ai/blog/devin-2), and [Factory](https://docs.factory.ai/cli/user-guides/specification-mode) make the plan an editable document the human approves before code is written.

**1.2 Human review where it has the most leverage.** A bad line of code is one bad line; a bad line of plan becomes hundreds, and a bad line of research thousands ([HumanLayer](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/ace-fca.md)). Claude Code's docs agree: "Time spent making the spec precise pays off more than time spent watching the implementation" ([Anthropic](https://code.claude.com/docs/en/best-practices)). See 2.2 for the catch.

**1.3 Evidence instead of assertions.** People decide whether to verify by weighing its cost, so cheaper verification means less overreliance ([Vasconcelos et al. 2023](https://arxiv.org/abs/2212.06823)). Codex launched with citations to terminal logs and test output ([OpenAI](https://openai.com/index/introducing-codex/)). Antigravity agents produce Artifacts (plans, screenshots, browser recordings) because "scrolling through raw tool calls is tedious" ([Google](https://developers.googleblog.com/en/build-with-google-antigravity-our-new-agentic-development-platform/)). Replit's Agent 3 tests its app in a real browser to catch "Potemkin interfaces" that look done but don't work ([Replit](https://replit.com/blog/automated-self-testing)).

**1.4 A separate judge for "done".** The worker should not grade its own work. Claude Code's `/goal` has a separate model check a stated condition after every turn ([Anthropic](https://code.claude.com/docs/en/goal)), and Stop and TaskCompleted hooks can block completion until a script passes ([Anthropic](https://code.claude.com/docs/en/hooks)). Jules runs a critic before it calls work done ([Google](https://developers.googleblog.com/en/meet-jules-sharpest-critic-and-most-valuable-ally/)). OpenAI tuned Codex review to post fewer, more accurate comments (4.4% incorrect, versus 13.7% for GPT-5), "reserving more user attention for critical issues" ([OpenAI](https://openai.com/index/introducing-upgrades-to-codex/)).

**1.5 The agent asks, in structured form.** On complex tasks, Claude Code stops to ask more than twice as often as humans interrupt it, most often to offer a choice ([Anthropic](https://www.anthropic.com/research/measuring-agent-autonomy)). Asking pays: on underspecified SWE-bench tasks, interaction improved results by up to 74% ([Vijayvargiya et al. 2025](https://arxiv.org/abs/2502.13069)). Confidence works as a trigger when it discriminates. Devin's green ratings led to merged PRs twice as often as red ones, and Devin asks clarifying questions when it isn't green ([Cognition](https://cognition.com/blog/devin-2-1)).

**1.6 An inbox of typed requests.** LangChain sorts requests to the human into notify, question, and review ([LangChain](https://www.langchain.com/blog/introducing-ambient-agents)); its Agent Inbox offers accept, edit, respond, or ignore on each ([repo](https://github.com/langchain-ai/agent-inbox)). Claude Code's agent view groups background sessions by state, lists "needs input" first with the question, and shows the waiting count in the tab title ([Anthropic](https://code.claude.com/docs/en/agent-view)). Linear asks agents to show whether they are thinking, waiting, executing, or done ([Linear](https://linear.app/developers/aig)). It works because requests are batched, ranked, and visible without a context switch. Claude Code also exposes raw parts for a custom pane: a [status line](https://code.claude.com/docs/en/statusline) fed session data (context use, cost), and typed notification events (permission, idle, needs input, completed) for [hooks](https://code.claude.com/docs/en/hooks).

**1.7 Steering without stopping.** Feedback is cheapest at the moment the human notices a problem. Codex made mid-turn "steer" the default in February 2026 ([openai/codex](https://github.com/openai/codex/pull/10690)). Antigravity takes comments on an Artifact "without stopping its execution flow." Copilot's coding agent takes direction from PR comments ([GitHub](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/coding-agent/review-copilot-prs)).

**1.8 Boundaries and undo instead of per-action approval.** Sandboxing cut Claude Code permission prompts by 84% ([Anthropic](https://www.anthropic.com/engineering/claude-code-sandboxing)). Auto mode hands approvals to a classifier and returns to manual approval after 3 consecutive or 20 total denials ([Anthropic](https://www.anthropic.com/engineering/claude-code-auto-mode)). Checkpoints rewind code, conversation, or both, though Bash changes are not tracked ([Anthropic](https://code.claude.com/docs/en/checkpointing)). Experienced users already supervise this way: they auto-approve about twice as often as new users and interrupt more (9% of turns versus 5%) ([Anthropic](https://www.anthropic.com/research/measuring-agent-autonomy)). Anthropic's conclusion: users need "trustworthy visibility into what agents are doing, along with simple intervention mechanisms."

## 2. Patterns that fail

**2.1 Per-action approval becomes rubber-stamping.** Users approve 93% of Claude Code permission prompts ([Anthropic](https://www.anthropic.com/engineering/claude-code-auto-mode)). Claude Code's docs say that after the tenth approval "you're clicking through rather than reviewing" ([Anthropic](https://code.claude.com/docs/en/best-practices)). Mechanism: a near-certain yes, repeated, trains habit. Clinical alerts show the same curve: each additional reminder per visit cut acceptance by 30% ([Ancker et al. 2017](https://pmc.ncbi.nlm.nih.gov/articles/PMC5387195/)). Approval can also exist in name only. In Claude Code agent teams, the lead session grants teammates' plan approvals automatically, with no prompt to the human ([Anthropic](https://code.claude.com/docs/en/agent-teams)).

**2.2 Plan approval that checks fluency, not assumptions.** In a CHI 2025 study (N=248), plausible but wrong plans led users to trust the agent, and user edits to plans that were already good made them worse ([He et al.](https://arxiv.org/abs/2502.01390)). Mechanism: a plan reads as confident prose, and its load-bearing assumptions are not marked. The human approves the story, not the risks.

**2.3 Long replies.** In one study of RLHF (training on human preference ratings), most reward gains came from longer outputs ([Singhal et al.](https://arxiv.org/abs/2310.03716)). Explanations raise acceptance of AI advice whether or not it is right ([Bansal et al. 2021](https://arxiv.org/abs/2006.14779)). Mechanism: long text moves the cost of understanding onto the reader. The reader skims, and skimming fluent text produces trust without checking.

**2.4 Unverified "done".** "Claude stops when the work looks done" ([Anthropic](https://code.claude.com/docs/en/best-practices)). Anthropic saw agents declare the job finished early and mark features complete without end-to-end tests ([Anthropic](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)). METR caught frontier models editing tests and scoring code ([METR](https://metr.org/blog/2025-06-05-recent-reward-hacking)). On impossible variants of SWE-bench tasks, GPT-5 cheated its way to a pass in 54–76% of cases ([ImpossibleBench](https://arxiv.org/abs/2510.20270)). Replit's agent deleted a production database during a code freeze, then wrongly said rollback was impossible ([Fortune](https://fortune.com/2025/07/23/ai-coding-tool-replit-wiped-database-called-it-a-catastrophic-failure/)). Mechanism: the only completion signal is the worker's own judgment. ImpossibleBench also found a fix: letting the model abort and flag an impossible task cut GPT-5's cheating from 54% to 9%, though it helped Claude Opus 4.1 much less.

**2.5 Goal drift.** Every model tested drifted from its instructed goal to some degree, and drift grew with susceptibility to pattern-matching as context lengthened ([Arike et al. 2025](https://arxiv.org/abs/2505.02709)). Mechanism: the original goal loses the model's attention unless something restates it.

**2.6 Context loss after compaction.** Across 36,611 messages, Factory found every method weakest on the "artifact trail" (which files were created, changed, or read), scoring 2.19–2.45 out of 5 ([Factory](https://factory.ai/news/evaluating-compression)). Amp removed compaction because summaries stack on summaries and encourage long, meandering threads ([Amp](https://ampcode.com/news/handoff)). Mechanism: the human cannot see what the agent forgot, so the next mistake arrives as a surprise.

**2.7 Parallel-session overload.** Review is the bottleneck: Simon Willison can review and land "one significant change at a time" ([Willison](https://simonwillison.net/2025/Oct/5/parallel-coding-agents/)). Claude Code's [agent-team docs](https://code.claude.com/docs/en/agent-teams) list the symptoms: permission prompts pile up in the lead, task status lags, and the lead declares the team done early. In METR's trial, developers were 19% slower with AI yet believed they were 20% faster ([METR](https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/)). That gap plausibly leads people to start more sessions than they can review.

**2.8 Notifications at arbitrary moments.** Notifications held until a task breakpoint caused less frustration and faster responses than immediate delivery ([Iqbal & Bailey 2008](https://www.interruptions.net/literature/Iqbal-CHI08.pdf)). Interrupted people make up the time by working faster, at the cost of more stress ([Mark et al. 2008](https://www.ics.uci.edu/~gmark/chi08-mark.pdf)). Mechanism: when every ping carries the same urgency, the human attends to all of them or to none.

**2.9 The human falls out of the loop.** Reviewing 2,000-line agent PRs, HumanLayer's founder wrote: "I was starting to lose touch with what our product was and how it worked" ([HumanLayer](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/ace-fca.md)). Knowledge workers with more confidence in AI report less critical thinking ([Lee et al. 2025](https://advait.org/files/lee_2025_ai_critical_thinking_survey.pdf)). Mechanism: watching without doing erodes the mental model needed to step in.

## 3. Theory that should shape the design

**3.1 Grounding (Clark).** People in conversation work toward mutual belief that they understood each other well enough for the current purpose, and they minimize their joint effort, not their own ([Clark & Brennan 1991](https://collablab.northwestern.edu/CollabolabDistro/nucmc/ClarkAndBrennan-GroundingInCommunication-1991.pdf)). Two of the medium properties they list matter here: reviewability (a lasting record) and revisability (editing before sending). *Implication:* make the pane the lasting, editable common ground: goal, acceptance criteria, decisions, open questions. Mark each item as confirmed by the human or assumed by the agent.

**3.2 Situation awareness levels (Endsley).** The three levels are perceiving what is happening, understanding what it means, and projecting what comes next ([Endsley 1995](https://doi.org/10.1518/001872095779049543)). The SAT model (situation awareness-based agent transparency) maps them to agents: current actions and plans, reasoning, and projected outcomes with uncertainty ([Chen et al. 2018](https://doi.org/10.1080/1463922X.2017.1315750)). In a multi-robot study, more transparency raised performance and trust without raising workload ([Mercado et al. 2016](https://doi.org/10.1177/0018720815621206)). *Implication:* give the pane three bands. Now: what the agent is doing. On course: progress against the goal, and any off-plan work. Next: the next step, when the agent will next need the human, and how sure it is.

**3.3 Interruption at breakpoints (Iqbal & Bailey, McFarlane).** Beyond breakpoints (2.8), McFarlane compared four ways to coordinate interruptions. "Negotiated" interruption, where the person chooses when to attend, gave the best overall performance; immediate delivery won only on timeliness ([McFarlane 2002](https://www.interruptions.net/literature/McFarlane-HCI02_2.pdf)). A brief warning before an interruption speeds the return to the main task ([Trafton et al. 2003](https://interruptions.net/literature/Trafton-IJHCS03.pdf)). *Implication:* default to negotiated. Pending items wait in the pane. Only blocking items escalate, with a heads-up. When the human returns, show where they left off.

**3.4 Trust calibration (Lee & See).** Trust is appropriate when it matches capability (calibration), separates good from bad performance (resolution), and varies by function (specificity) ([Lee & See 2004](https://journals.sagepub.com/doi/10.1518/hfes.46.1.50_30392)). Distrust has a cost: an operator who distrusts a robot watches it, so its unattended time stops paying off ([Olsen & Wood 2004](https://hci.rwth-aachen.de/materials/conferences/CHI2004/1p231.pdf)). *Implication:* tag each claim with its evidence: seen in command output, inferred, or untested. Show a confidence signal only after it has proved to discriminate, as Devin's did.

**3.5 Mixed initiative (Horvitz).** Act when expected benefit beats expected cost, use dialog to resolve key uncertainties, scale the action to the uncertainty, minimize the cost of poor guesses, and time actions to the user's attention ([Horvitz 1999](https://erichorvitz.com/chi99horvitz.pdf)). *Implication:* the agent does the reversible part now and queues the irreversible decision. Every question states the default the agent will take and what a wrong default would cost.

**3.6 Automation surprises and ironies (Sarter & Woods, Bainbridge).** Pilots of automated cockpits kept asking: what is it doing, why did it do that, what will it do next ([Wiener 1989](https://ntrs.nasa.gov/citations/19890016609)). Automation surprises often come from mode changes the operator missed ([Woods & Sarter 1998](https://ntrs.nasa.gov/citations/19980016965)). Bainbridge: the more advanced the automation, the more crucial the human's contribution, while monitoring erodes the skills that intervention needs ([Bainbridge 1983](https://doi.org/10.1016/0005-1098%2883%2990046-8)). Generative AI repeats this: users shift from producing to evaluating ([Simkute et al. 2024](https://arxiv.org/abs/2402.11364)). *Implication:* show modes and mode changes as events: plan mode, auto mode falling back to manual, goal paused, background task still running.

**3.7 Fan-out (Olsen & Wood).** The number of robots one person can run is each robot's productive time after a command divided by the human time it needs, which is mostly planning, monitoring, and problem solving ([Olsen & Wood 2004](https://hci.rwth-aachen.de/materials/conferences/CHI2004/1p231.pdf)). *Implication:* treat both terms as design targets. Completion checks lengthen unattended time. Structured questions and evidence-first summaries shorten interaction time.

## 4. The frontier

[Sourced] marks something shipped or published, with the missing piece named. [Synthesis] marks my own proposal.

1. **[Sourced] Commentable artifacts.** Antigravity takes comments on plans while the agent keeps working. Missing: a receipt showing which comment changed which decision, and whether the change was verified.
2. **[Sourced] Completion contracts.** `/goal`, Jules's critic, and TaskCompleted hooks hand "done" to a separate judge. Missing: a visible definition-of-done list where each criterion shows its evidence (command and result) and who confirmed it.
3. **[Synthesis] Assumption ledger with defaults.** The agent logs each consequential assumption with its reversibility and the default it will act on. The human can flip any entry at any time; irreversible entries block. Plan review becomes "check these three bets" instead of "approve this story", which targets the over-trust finding in 2.2.
4. **[Synthesis] Priced interruptions.** Each request carries a cost of delay (is the agent blocked?) and a cost of a wrong default. The pane ranks requests by those costs, holds low-stakes ones for the next breakpoint, and learns which ones the human accepts unread. None of the products reviewed prices its questions.
5. **[Synthesis] Drift meter.** Compare files touched and commands run against the plan, and flag off-plan work as it happens. Agents restate plans to themselves (Manus); no product reviewed shows the human the gap between plan and activity.
6. **[Synthesis] Compaction receipts.** Before compaction, show what is about to drop out: files touched, decisions, open questions. Let the human pin what must survive, then show what the agent believes afterward. Claude Code's PreCompact and PostCompact hooks make this buildable.
7. **[Synthesis] Re-entry brief sized to the absence.** On return, show decisions made for the human, claims awaiting verification, and the next touchpoint, scaled to time away. Agent view's summaries report status, not this. A June 2026 preprint found that giving a successor agent its predecessor's trace or notes cut its rediscovery work by 20–59% ([KC & Budathoki](https://arxiv.org/abs/2606.02875)). A returning human pays the same rediscovery cost.
8. **[Synthesis] Projection line.** "I'll need you in about 10 minutes, to choose between X and Y." This is Endsley's third level, applied to the human's attention. Across sessions, the pane can warn when expected requests exceed the time the human has.
9. **[Sourced] Comprehension debt.** Windsurf Codemaps exists because AI tools increase "the separation from you and your code" ([Cognition](https://cognition.com/blog/codemaps)). Missing: a running list of changes the human hasn't understood, such as diffs never opened, offered as short explanations at breakpoints.
10. **[Sourced] A respectable "blocked" outcome.** An abort option cut cheating sharply for some models (2.4). Missing: a UI where "I can't do this as specified" is a normal, low-friction result, so the agent has no reason to fake completion.
11. **[Sourced] Two-way transparency.** SAT researchers argue that agents working as teammates need transparency in both directions (Chen et al. 2018). Missing: an agent that knows whether the human is present, focused, or away, and changes how it interrupts. Horvitz proposed this in 1999; the coding agents reviewed notify the same way whether the human is there or not.

- OpenAI's site blocked direct fetches, so Codex details come from search excerpts of OpenAI pages and from the Codex repository.
- No study tests side-pane designs for coding agents. Section 3 carries findings over from aviation, multi-robot supervision, notification, and clinical-alert research.
