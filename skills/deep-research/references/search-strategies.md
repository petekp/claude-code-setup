# Search strategies

Start from the user's exact question and any supplied source. Add alternate terminology when results reveal it; do not run a preset number of query variants.

| Need | Useful next search |
| --- | --- |
| Installed software behavior | Local implementation and tests, then documentation for that version |
| Current product capability | Official reference, changelog, or release note for the named product |
| Original research | Paper or dataset behind the claim, then replications or critical studies |
| Historical decision | Relevant commit or PR, followed by linked issues and discussions |
| Comparison | The same evaluation criteria and versions for every option |
| Conflicting accounts | Original evidence, dates, definitions, and the scope each account covers |

If results are irrelevant, add the domain or an exact phrase. If sparse, remove a constraint or try a synonym. Use date filters for facts likely to change; do not exclude foundational evidence merely because it is old.

Open the relevant source instead of relying on a search snippet. Follow citations that bear on the question. Use a browser when content requires interaction or authenticated access; follow the user's browser and authentication rules.

Keep a search log only when a reproducible research record is requested or missing evidence needs explaining. Record useful queries and coverage limits, not every tool call.
